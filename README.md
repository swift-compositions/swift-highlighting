# swift-highlighting

Use this package when source code is to be drawn the way an editor draws it, with each word coloured by the role it plays: on a page, in a slide, in a film. `Highlighting` holds the values every highlighter gives: a `Highlighting.Token`, a run of text with its `Highlighting.Role`. Lines are arrays of tokens, and a file is an array of lines. Nothing here draws: pick a colour, weight or style per role yourself. To highlight Swift, enable the `Swift` trait and call `Highlighting.Swift.lines(of:in:)` with the file to show and every `Highlighting.Swift.File` of the project it belongs to. It parses the file with swift-syntax and runs the compiler on the project to tell the project's own names from the system's. It runs on a Mac with Xcode or the Command Line Tools selected, and blocks the calling thread until the compiler has finished, so call it off the main thread.

## Laws

- The lines keep every character of the shown file: joining each line's token texts, and the lines with `\n`, gives back the file's text. A line break never sits inside a token, and an empty line is an empty array.
- `plain` is everything not named below: punctuation, operators, whitespace, module names after `import`, local variables and parameters, and any name whose role cannot be decided. `keyword` is every keyword token, contextual ones such as `some` and `in` included where the parser reads them as keywords. `string` is a string or character literal's quotes, delimiters and text segments; the expressions interpolated into it get their own roles. `number` is an integer or floating-point literal. `comment` is a line, block or documentation comment, delimiters included.
- `declarationType` is the name a type declaration introduces (`struct`, `class`, `enum`, `actor`, `protocol`, `typealias`). `declarationOther` is the name a function declaration introduces, and the name of a stored or computed property declared in a type or at the top level of a file. A local variable's name is `plain`.
- A `project` name is declared in one of the files passed as `project`; a `system` name is declared in a module those files import. A name written as a type (`: View`, `[Tide]`) is `projectType` if a file of the project declares a type of that name and `systemType` otherwise. An attribute (`@State`, `@main`), its `@` included, is `projectType` by the same test and `systemMember` otherwise.
- A name used in an expression takes the role of the declaration the compiler resolves it to: a project declaration gives `projectType` when the name starts with an uppercase letter and `projectMember` otherwise; a system declaration gives `systemType` or `systemMember` the same way, except a system member that the module's interface marks `@_alwaysEmitIntoClient` or `@export`, which is `plain`, as an editor draws it. A local, a closure's parameter or an anonymous declaration gives `plain`. An argument label is `projectLabel` when the called name is the project's and `systemMember` when it is the system's.
- The project is compiled as written, for the Mac running the call, against the newest macOS SDK the selected developer directory has: its files are written under their names to a fresh directory in the system's temporary directory, which is removed afterwards. `shown` must be one of the project's files under the same name, or none of its names is resolved. Files that do not compile still give whatever references the compiler resolved.
- When the compiler cannot be run or does not resolve a name (no developer tools, no SDK, a file name that is not a valid relative path, a name in code it could not type-check), the call still returns every line. A name used in an expression is then `projectType` if a file of the project declares a type of that name, else `systemType` if it starts with an uppercase letter, else `plain`, and an argument label follows the role of its called name as above. Every other role is decided from the syntax alone and does not change.
